# 阈值登记

这张表回答三个问题：

1. **要解决什么问题** —— 一个数字改错了会怎样，为什么需要一张登记表。
2. **为什么只有两种来历** —— 可复算与选择，判据是什么。
3. **它能查出什么、查不出什么** —— 哪些错误会让门禁变红，哪些错误它完全看不见。

（本文说的「阈值」是指影响行为、又只能靠测量或判断定下来的常量。不是数字的判据表也算，它们登记在同一张表里。）

（下文与代码注释里的「设计说明」指作者的设计记录，它不随本仓库发布；引用只到章节名，用来回答「这个值当初为什么定成它」。读到「设计说明 §7」这样的引用时，看不到那份记录是正常的。）

## 1. 要解决什么问题

影响行为的数值常量散在 src/ 的多个文件与一个外部包里。改一个数会牵动召回结果、注入长度或写入耗时，从调用点看不出来。

没有登记时，来历会以三种方式丢掉：

1. **数字没有来历。** 下一个人不敢改，也不敢不改。
2. **来历与值分居两处。** 说明写在注释、设计说明或提交正文里，改一处漏一处，谁先过期看不出来。
3. **来历过期没人发现。** 换了编码模型，阈值还按旧模型的余弦分布定着，而没有任何一步会因此变红。

登记解决第 2、3 条。第 1 条补不上已有的数字（从没测过，就没有来历可写），它只能防新的：新写下一个没有来历的数值常量，覆盖核对会当场拦下（见第 7 节）。

## 2. 来历写在值旁边

值是 number，来历写在类型参数里，与值在同一个表达式上：

```ts
export const DELTA_PEAK = 0.06 satisfies ThresholdValue<
  'chosen',
  {
    area: '落位'
    why: '双峰拒绝线：前两名余弦差小于多少算「分不开」……'
    guardedBy: ['test/write.test.mjs']
    docKey: 'deltaPeak'
    docDefault: 0.06
  }
>
```

（这是 src/pipeline/write.ts 里的真实写法，省略了部分字段。第二个类型参数是类型字面量，成员用换行分隔、不写逗号。）

扫描器用 TypeScript 语法树把它读出来（src/threshold-types.ts 开头解释了为什么不放进运行时对象），运行时零成本，调用点不用改。

第二个类型参数的字段名不受类型约束：写错字段名不会编译报错，字段白名单由 scripts/print-thresholds.mjs 的 thresholdOriginProblems() 断言。这是有意的取舍 —— 约束写在检查里，类型层只负责「让来历有地方待」。

来历可以写在两处：常量定义处的 satisfies（大多数条目），或登记表 src/thresholds.ts 里的一条（搬不动的：内联表达式、非数值、静态读不出、外部包、派生自外部包的）。扫描器读两种来源，命令输出不区分。

## 3. 为什么只有两种来历

判据是**测量推不推得出这个值**，不是「现在有没有记录」。

| | 可复算（recheckable） | 选择（chosen） |
|---|---|---|
| 什么时候用 | 测过，且测量与该值之间有可复算关系：测量变了，值要跟着改 | 没有任何测量能给出它：设计判断、算法惯例、容量取舍、接口约束 |
| 必填 | tool（怎么复算）、finding（测出了什么） | why（为什么是这个值） |
| 其它字段 | encoderModel / scale / at（编码模型、语料条数、测量日期，原记录没有就留空，不猜）；缺前两个会进 --needs-review，缺 at 只进 --undated | guardedBy / area / failsWhen / affects 等，与可复算项相同 |
| 数字能出现吗 | 能，出现在 finding 与 display 里 | **why 里不许出现测量数字** —— 出现就说明该判可复算，那个数字该进 finding |

一条容易判错的规则：**曾有测量，但数值与测量条件都没留下 → 判可复算，缺的字段留空。**

理由：判「选择」等于宣布「不需要测量」，记录丢失就被写成了设计决定。留空会让 --needs-review 一直把它报出来，直到有人补上测量条件，或写进评审基线并说明为什么现在补不了。

## 4. 登记表怎么读

跑 node scripts/print-thresholds.mjs 得到一张表。2026-10-21 的规模是 137 行（一行可能是一个键的多个取值，也可能是几个同类键排在同一行），分三类：可复算 22 行、由公式算出 10 行、选择 105 行。

「由公式算出」是可复算的子类，不是第三种来历：值由代码里的算式推出，算式里的量一变值就跟着变。所以它判可复算，要重跑的不是标定而是复算，字段里写 formula: true，--needs-review 会跳过它。

六列：名称 / 当前值 / 段（作用在管线哪一段）/ 来历 / 可变条件（什么变了该重标）/ 定义位置（文件:行号）。两行真实例子：

| 名称 | 当前值 | 段 | 来历 | 可变条件 | 定义位置 |
|---|---|---|---|---|---|
| DEFAULT_THRESHOLDS.tauJoin | 0.78 | 落位 | 可复算 | 换编码模型；标定语料的领域混合度；误并与漏并的代价评估 | src/pipeline/write.ts:374 |
| TIER_SCALE_ANCHORS | 12→0.466 / 24→0.47 / 48→0.492 / 96→0.514 / 192→0.514 / 384→0.514 / 768→0.514 / 1374→0.525 | 注入 | 可复算 | 查询集（人工挑的 20 条相关 + 20 条无关）；换编码模型；语料的领域混合度 | lattice-calib:src/anchors.ts（外部包） |

表尾另有一节「不是数字，所以数值扫描本就捕不到」：SQL 文本、正则、类型枚举这类结构性常量逐条列出，并注明改名时要同步那一节。

## 5. 能跑的命令

| 命令 | 查什么 | 在门禁里 | 2026-10-21 的结果 |
|---|---|---|---|
| node scripts/print-thresholds.mjs | 覆盖核对：有没有未登记的数值常量、定位不到定义处的登记项、写了分叉却没解释的项 | thresholds | 137 行 |
| 同上加 --check-review | 评审基线：当前待评审条目是否都在基线里、基线里的名字是否仍是真实条目 | thresholds-review | 通过（needsReview 6 条 / unguarded 93 条；基线里已不在结果中的 0 条） |
| 同上加 --undated | 可复算、但没有记录测量时间的条目（只是信息，不拦） | thresholds-query | 13 条 |
| 同上加 --needs-review | 声明可复算、但缺编码模型与语料规模的条目 | 手工 | 6 条 |
| 同上加 --unguarded | 没有测试按常量名断言默认值的条目 | 手工 | 93 条 |
| 同上加 --doc-keys | 设计说明的键名 → 代码常量 → 文档给的默认值 | 手工 | 19 条，其中 5 条标着分叉 |

门禁里的三条（thresholds / thresholds-review / thresholds-query）读同一份扫描结果，只读源码，不需要模型与网络。整条门禁在仓库根跑 node scripts/check-all.mjs，**要带上当前分支名**：GIT_BRANCH 没传时脚本打印「分支：未知」，那不叫通过（bash 写法 GIT_BRANCH=$(git branch --show-current) node scripts/check-all.mjs；PowerShell 先设 $env:GIT_BRANCH）。退出码 0 = 全部通过，1 = 任一检查不通过；--undated 进 CI，但它只打印、不判红。

--doc-keys 是定位工具：文档改了一条，用它找受影响的登记项。节选（真实输出）：

- tauJoin ｜ DEFAULT_THRESHOLDS.tauJoin ｜ 文档默认 0.75 ｜ 代码 0.78 ｜ 分叉
- tauLex ｜ DEFAULT_THRESHOLDS.tauLex ｜ 文档默认 0.12 ｜ 代码 0.05 ｜ 分叉
- viewBudget ｜ DEFAULT_BUDGET ｜ 文档默认 6000 ｜ 代码 6000 ｜ 一致

分叉不是错误，但必须在登记项里写原因（divergence 只写原因，文档值从 docDefault 读，不抄第二份）。

## 6. 评审基线只许变短

待评审条目（缺条件的可复算项、没有测试守住默认值的项）现在共 6 + 93 条，记在 thresholds-review-baseline.json 里。这是一份**临时清单**，规则是只允许变短：

1. 名字必须在冻结名册 thresholds-inventory.json 里 —— 凭空加一个名字会红；
2. 名册里的名字必须仍是真实条目 —— 条目改名或删除，名册与基线要一起改；
3. 每条写清为什么现在补不了；
4. 当前查询结果必须都在基线里 —— **新出现的待评审条目不能靠加进基线消掉**；
5. 基线里已经不在结果中的项不报错，删掉即可（上面的输出会报这个数字）。

冻结名册记的是「阈值迁移完成时已有的条目」，新写的阈值默认不在里面。这一层设计只有一个目的：让「把新债记进清单」这一步在代码评审里看得见。

两个集合都空了，删掉这两个文件。

## 7. 它能查出什么

每条都对应一个真的会让门禁变红的条件：

- **新加一个数值常量没登记** → 覆盖核对红。scripts/print-thresholds.mjs 开头的注释里记着一次实测：正则扫描只认「整行恰好是 const X = 裸数字」，表达式型常量（例如 12 * 3600 * 1000）完全隐身，扫描器退出码 0、日志里一个字都没有 —— 所以用语法树而不是正则。
- **登记项指的文件或片段与源码对不上** → 报「定位不到定义处」。
- **默认值被藏进运行时对象**（常量只是被引用，实际生效值在别处写死）→ 单独报出来。
- **显示模板里的数字与常量脱钩** → 红。显示值也写成断言：display 写 '{v} ms' 时，打印出来的是当前值，常量改了它跟着改；写成 '0.9 ms' 这样的固定字符串，常量一改就与它脱钩，门禁变红。
- **写了分叉却不给文档默认值** → 红（没有可比对的文档值）。
- **声明可复算但缺编码模型或语料规模** → 进 --needs-review；没写进基线就红。
- **没有测试按常量名断言默认值** → 进 --unguarded；没写进基线就红。

## 8. 它查不出什么

这一节同样重要：不要把绿色当成正确。

- **值本身对不对。** 检查的是「来历字段齐不齐、指得到不到」，不是「0.78 这个数标定得对不对」。标定错了而字段齐全，全绿。
- **来历判得对不对。** 可复算与选择的划分是人做的。把一条该可复算的写成选择，机器看不出来 —— why 只查非空，不查里面有没有测量数字（第 2 节那个 why 里就写着 0.06，检查照样通过）。剩下的靠评审看。
- **why 写得好不好。** 「历史如此」也能通过检查。
- **外部包里的值能不能复算。** 标定包 lattice-calib 的锚点表以「外部包」的身分登记（定义位置写 lattice-calib:src/anchors.ts），本仓库不复算它；那边怎么守住是那个包自己的事。
- **运行时实际生效的值。** 档位阈值登记的是锚点表（12 → 0.466 … 1374 → 0.525），运行时由 briefMinFor(db) 按库的 atom 数在锚点之间插值（log2 尺度、两端夹紧）。表里没有「当前这个库的实际阈值」这一列。
- **非数值的结构性常量。** SQL 文本、正则、类型枚举只列名字，改不改变得靠人发现。

## 9. 新增一个阈值要做什么

1. 写在常量定义处，用 satisfies 带来历。可复算的连 tool / finding / encoderModel / scale / at 一起写；条件确实没有就留空。搬不动的几类（内联表达式、非数值、静态读不出、外部包、派生自外部包的）改走登记表 src/thresholds.ts，照已有条目写，字段同名，只是不写在常量旁边。
2. 跑总览与三个查询（--needs-review / --unguarded / --undated）：新出现的待评审项必须当场合规，不能靠加进基线消掉 —— 要进基线，先把名字加进冻结名册，那一步在评审里看得见。
3. 加一个按常量名断言默认值的测试，并把测试文件写进 guardedBy；否则它会进 --unguarded。测试放 test/ 下的 *.test.mjs，用 node:test 的 describe / it 与 node:assert/strict，并在 test/run.mjs 里 import 到；单独跑 node test/run.mjs。
4. 跑一遍门禁（见第 5 节）确认没变红。只关心评审基线时可以单跑 node scripts/print-thresholds.mjs --check-review —— 新出现的待评审项、名册里过期的名字都在这一步报出来。

## 10. 与其它文档的分工

- 本文件：这张表是什么、怎么读、能查出什么、查不出什么。
- docs/DEVELOPMENT.md 的「阈值登记：来历与评审」一节：字段全表（每个字段填什么）、评审纪律原文、档位阈值按库规模重标的实测来历。**字段怎么填以那一节为准** —— 写错字段名不会编译报错，只有扫描器会报。
