## 0. 四步跑通：装 → 写一条 → 召回一次 → 读注入段

### 0.1 装

0.9.0 还没发布到 npm，所以 `dsh plugin add dsh-lattice` 在这一版上跑不通。先按
[README 的安装一节](../README.md) 从源码构建，把构建产物复制进 profile 的 `node_modules`。
发布到 npm 之后，最短路径才是：

```bash
cd <DSH_HOME>/profiles/<profile>
dsh plugin --profile <profile> add dsh-lattice
```

这两条要在装了宿主的机器上跑：`dsh` 是宿主提供的命令，不在本仓库里，所以本仓库的脚本与门禁都不会跑到它
（本文无法在仓库内实跑核对）。`<profile>` 是 profile 目录名（本仓库声明可用的两个是 `web` 与 `desktop`，见 `package.json`）。

装完**重启宿主**：插件在宿主里是复制过去的实体，不重启读到的是旧版本（`package.json` 里 `requiresRestart` 为 `true`）。
重启后调一次 `lattice_ping`，核对三件事：`version` 与你要用的版本一致；`tools` 里有五个名字（`lattice_ping` / `lattice_write` / `lattice_recall` / `lattice_expand` / `lattice_list`）；
`encoder` 不是 `off`（除非你就是要用纯词面模式）。
如果 `lattice_ping` 报「没有这个工具」，说明插件没加载：到该 profile 的 `package.json` 里看
`dependencies` 与 `dsh.profile.bundles` 是不是都写了 `dsh-lattice`。

**不经宿主时怎么核**（本仓库的验证脚本走的就是这条）：构建产物是 ESM 模块，导出 `apply(ctx, config)`。
`ctx` 只需实现三件事 —— `get('tools')` 返回 `{register}`、`get('webServer')` 返回 `{register}`（没有就不注册界面那组路由）、
`effect(fn)` 接收清理函数并返回一个（返回值不是函数会报 `ctx.effect is not a function`）。注册进表的每个工具是
`{name, description, parameters, execute(args)}`，`execute` 返回拼好的文本。配置项与宿主里那一套相同；两个容易漏的：
`dataDir` 留空时按 `$DSH_HOME/lattice` → `~/.dsh/lattice` → 当前目录的 `.lattice` 依次解析（`lattice_ping` 的 `dataDir` 报的就是解析结果），
`encoderCacheDir` 留空时用 transformers.js 的默认缓存位置 —— 离线机器上那里没有模型，召回会退回纯词面（§4.1）。

### 0.2 写一条

一次调用只写一件事。下面这条可以照着换成你要记的内容：

```
lattice_write
  text: "本仓库的门禁必须带分支名跑：GIT_BRANCH=$(git branch --show-current) node scripts/check-all.mjs；不传时输出「分支：未知」，那不是通过。"
  kind: "步骤"
  refs: ["门禁", "check-all", "分支：未知", "全绿"]
  origin: "user"
```

回执长这样（数值是示例；有「标记」一行时它的含义见 §2.7）：

```
已写入记忆 #37：并入已有主题 #12
入口 5 条（其中显式声明 4 条）
```

回执每一行的含义见 §2.7。**写入是显式动作**：没有「轮次结束自动沉淀」，不调用就不会写。

### 0.3 召回一次

```
lattice_recall
  query: "门禁怎么跑"
```

返回是一段拼好的文本，不是数组。示例（数值是示意；纯词面模式下首行下面会多一句
「（编码器不可用，本次为纯词面召回）」，见 §4.1）：

```
库：atom 128 / topic 96 / entry 341 / edge 57

【入选】
- [37·我] 门禁必须带分支名跑：GIT_BRANCH=$(git branch --show-current) node scripts/check-all.mjs；不传时输出「分支：未知」…
- [42] 门禁第 7 步是文档一致性检查，新文档会被它扫到…
预算装不下了，还有 4 条未列。

（关系可显式声明：lattice_write 的 edges。）
```

判空时上面这一整段都不出现，只剩判空那一句（§4.3）；降级说明（§4.2）排在判空句之前，说的是这次走了哪条路，不是结论。

### 0.4 注入段里有什么

注入只有一段 `【入选】`，按相关度降序，一行一条记忆正文。旧形态的 `【入口】`（主题入口词）
与 `【路】`（一跳线索）在 0.5.0 取消 —— 它们不是结果，却和结果混在同一段文本里，读的人得
自己判断哪一行能当依据。

| 位置 | 里面是什么 | 什么时候用它 |
|---|---|---|
| **【入选】** | 命中的记忆正文，每行以 `- [id·标记] 正文` 开头。标记只标需要区分的：`·我` = 用户亲口说的；`·导入` = 外部来源；`·已被 #N 取代` = 已修订；`·疑似应拆分（切点按长度，未判内容）` = 写入时按长度切出来的候选（可能带段数，如「（3 段，切点按长度，未判内容）」）；`·用户已确认应拆分（可按内容重写并声明 supersedes）` = 人在界面上确认过；`·用于：…` = 这条曾经被用来回答什么，只挂在待拆分候选上。被取代的旧条默认不进这一段：它们被压掉，只在段末留一行 `[另有 N 条已被取代，未列出]`；要看旧条用 `lattice_expand`（§2.4） | 直接引用、当依据。id 就是 `lattice_expand` 的入参 |
| **段末的说明行** | 三种「少给了」都说明原因，发生了才出现：`[另有 N 条已被取代，未列出]`、`[另有 N 条与同源内容重复，未列出]`、`预算装不下了，还有 N 条未列。` | 数清楚少给了几条、为什么少 —— 三种都是系统主动压的，不是召回失败 |
| **最后一句** | 固定的工具提示（关系可显式声明）。候选耗尽、只找到一条时它仍在，另加一句对应说法（见 §0.5）；判空时它整句不出现 | 不需要读 |

单次注入的字符预算默认 5000 字符（配置项 `viewBudget`，可配范围 1000–20000；单次调用可用 `budget` 覆盖，`budget` 本身不做范围校验，见 §6）。
它只是**上限**：内容少时装不满，判空时是 0 字符。装填按相关度降序逐条进行，装到装不下为止，
**不分段分配配额**：旧形态按 55/20/25 分三段，实测只用到 76% 预算（约 1400 字符既没给锚也没被别的段用上）。
单条超过 1200 字符时截断，所以「这条看起来变短了」是单条上限，不是召回变差。

### 0.5 六种情形各有一句固定说法

判空的结论与「候选耗尽」看起来像，含义相反：一个是「库里没有」，一个是「库里有但只找到这么多」。
措辞必须不同，调用方也只能靠这几句区分。

另有两句只在**参考线自己失效**时出现（库的内容面比判定用的问句宽）：命中非空时是
`这个库的内容面比判定用的参考问句宽，判空这一步关掉了；以下是按相关度列出的前几条。`，
一条都没命中时后半句换成 `这次没有相关度靠前的条目。`。

| 情形 | 返回里出现的话 |
|---|---|
| 这条查询的最高余弦没到本库参考线 | `库里没有针对这个问题的内容。`（此时一条记忆行都不给） |
| 库里的条目比参考问句集还少（少于 48 条） | `库里只有 N 条，判定还不可靠；以下是按相关度列出的前几条。` |
| 候选池用完了 | `候选用完了，只有 N 条。` |
| 只找到一条 | `只找到一条相关的。` |
| 预算装不下 | `预算装不下了，还有 N 条未列。` |
| 判定通过、但一条都没命中 | `没有找到相关记忆。` |

## 1. 什么时候该查记忆

`lattice_recall` 的工具描述只有一句判据：「**答案取决于「之前定过什么」的问题先查；与历史无关的常识不必查。**」
下面把同一句判据展开成可核对的情形 —— 不是另一套判据，是这一句在具体场景里的样子。

### 1.1 会去查的四类情形

| 情形 | 典型问法 | 查什么 | 看什么信号 |
|---|---|---|---|
| **用户提过的事实与偏好** | 「还用上次那个方案」「按我的习惯来」 | 用户说过的事实、决定、偏好 | 命中行带 `·我` 的优先；没有 `·我` 的是模型自己总结的，引用前要说明 |
| **项目既有约定** | 「这个仓库怎么跑门禁」「提交前要做什么」 | 约定、命令、参数、命名 | 多条互相矛盾时以更新的那条为准；被取代的旧条在召回里被压掉，要看它得按 id 展开，展开的首行带 `已被 #N 取代` |
| **踩过的坑** | 「为什么这里不能用那个做法」 | 踩坑记录与原因 | `kind` 是「坑」时，通常是当初的具体做法加后果，照着避让 |
| **之前讨论过的方案** | 「上次说的那个办法」「我们不是试过吗」 | 讨论过的方案、结论与放弃理由 | 召回为空或相似度低时，**换用户当时的说法再查一次**，不要直接答「没聊过」 |

四类的共同点：答案不在当前对话里，而在**过去**。答案能直接从当前对话或公开常识拿到的，就不属于这四类。

### 1.2 不该查的边界

| 不该查 | 为什么 | 该做什么 |
|---|---|---|
| **与历史无关的常识问答** | 库里不会有比常识更好的答案；查了只会拿到一堆不相关条目，还容易被当成依据 | 直接答 |
| 当前对话里刚说过的内容 | 它在上下文里，不在库里；库里可能有旧版本，查了反而容易拿错 | 直接读对话 |
| 要现算、现查外部的事（今天的行情、某个网页的内容） | 记忆存的是当时的结论，不是实时数据 | 用对应的外部工具，不要用记忆代替事实来源 |

**边界怎么判**：问自己「如果库是空的，这个问题还能答对吗」。答得对 → 不必查；答不对 → 查。

### 1.3 查完看什么信号

- 首行「库：atom / topic / entry / edge」是**库的规模**，不是命中数。库很大却只回了几条，说明这次问法没打到入口。
- 「库里没有针对这个问题的内容。」= 判定这条查询在本库里几乎没有对应内容。**不要把它当成「库里没有这件事」**：
  判定按「本库无关问句的最高余弦」划线，边界上的真内容会被判成没有。换用户的原话、俗称或报错原文再查一次。
- 「候选用完了，只有 N 条。」= 库里有，但只有这么多。这个和上一句是相反的意思，别混。
- 段末的「另有 N 条…」是系统主动压掉的数量与原因，数得出来，不是召回失败。
- 想先知道「库里有什么」，用 `lattice_list`（目录视图，不是搜索）：

```
lattice_list
  kind: "坑"
  limit: 10
```

## 2. 一条记忆怎么写

### 2.1 text：结论式、可独立读懂

| 要求 | 判据 | 不满足会怎样 |
|---|---|---|
| **一条一件事** | 能用一句话概括，概括里不需要「以及」「顺便」 | 长文本会被按句切成多条，语义在切点处分开 |
| **能独立读懂** | 不依赖上文；「它」「上次那个」都有明确所指 | 半年后召回出来，读的人（包括你）不知道它在说什么 |
| **首句可当摘要** | 第一句本身就是这条的摘要 | 目录视图的摘要取正文**第一句**（按句末标点切，最多 48 字）：第一句是半句，列表里就是半句；正文整段只有表格或围栏代码块时摘要为空，列表里看不见内容 |
| **长度** | 默认上限 600 字；低于 12 字直接拒收 | 超过 600 字按句边界切成多条（每条都标「待拆分」位）；低于 12 字说明它该并进解释它的那条记忆 |

上限 600 字与迁移规范共用同一个界；下限 12 字只用于写入（迁移侧的下限是 80 字，那是切卡片小节用的）。两条都不可配。
一次写入最多切成 8 段（固定值）：要切超过 8 段时整条拒收，让你自己按主题拆成多次写入 ——
那条回执会说明「未写入」以及为什么。

### 2.2 kind：六类怎么选

判据只有一句：**这条记忆回答的是哪一种问题**。

| kind | 判据 | 例子（只示范形状，不是本库的真实记录） |
|---|---|---|
| **结论** | 一个能脱离上下文单独成立的判断 | 「本插件只有工具、没有 hook：写入必须显式发起，没有轮次结束自动沉淀。」 |
| **坑** | 按某个做法会出错，而且错得不显眼 | 「在 worktree 里对 node_modules 用递归删除会跟随链接删掉主目录：先判断是不是链接，再删链接本身。」 |
| **命令与参数** | 一条要照抄的命令，或一组要照抄的参数 | 「门禁：GIT_BRANCH=$(git branch --show-current) node scripts/check-all.mjs。」 |
| **环境** | 这台机器或这套部署的既成事实（版本、开关、可用性），不是任何人做的决定 | 「离线环境要事先缓存向量模型；没缓存时召回仍可用，只是退回纯词面。」 |
| **步骤** | 一串有先后顺序的动作 | 「合并前：切回默认分支 → 签出新分支 → 带分支名跑一次门禁。」 |
| **数据** | 一次测量的结果，带口径（样本量、单位、时间） | 「在 1374 条 atom 的库、20 条人工提问上，相关查询的目标文档命中率是 90%。」 |

三条规则：

1. 认不出的值按「结论」记，**回执会说明**（不会静默改写）。
2. 历史写法「参数」在写入时归一为「命令与参数」，查询时两种写法都匹配 —— 不要因为查询能匹配就继续写旧值。
3. kind 是**记忆自己的属性**，不是目录：它不参与排序，只用于筛选与浏览。

### 2.3 refs：以后会怎么找它

`refs` 写「用户以后可能用来找它的说法」，不是分类标签。

- 写**另一种说法**：俗称、缩写、报错原文、用户的口头叫法。例：`["装不上", "EPERM", "符号链接失败"]`。
- 不写**非检索词**：「重要」「todo」「参考」这类词不会有人拿来当查询。
- 不抄正文首句：正文本来就在检索范围里，`refs` 要加的是正文里没有的说法。

不给 `refs` 也能写：入口词会从正文里自动抽（之后还会从召回里学），条数随正文长度变化。
只是正文里没有的说法 —— 俗称、缩写、报错原文 —— 不会自己出现；想一开始就命中，写进 `refs`。

### 2.4 supersedes：改口时用

- **什么时候用**：新结论取代旧结论（旧条过时、写错了、情况变了）。
- **写什么**：旧条的记忆 id（不是序号）。
- **会发生什么**：旧条被标记「已被 #N 取代」，**不删除**；之后召回默认只给新条，旧条被压掉，注入段末尾留一行
  `[另有 N 条已被取代，未列出]`。要看旧条：`lattice_expand` 仍能展开，`lattice_list` 里也带「已被 #N 取代」。
- **不做什么**：不修改旧条正文，不删除任何内容。
- **边界**：id 不存在时回执说「注意：要取代的记忆 #N 不存在，未建立取代关系。」；写入被按长度切成多条时，
  取代只落在**第一条**，回执会写明「（切分后的第一条）」。

```
lattice_write
  text: "门禁现在还必须传 GIT_BRANCH，否则文档一致性那步会报「未知」。门禁怎么跑见 #37。"
  kind: "结论"
  supersedes: 37
```

这次写入的回执多一行：`已把 #37 标记为被 #38（本条）取代（旧条不会删除）。`

**撤销一次改口用 `unsupersede`**：传被取代的那条 id，只清它的「已被 #N 取代」标记 ——
不删行、不改正文，也不动取代它的那条。三种回执：

| 情形 | 回执原文 |
|---|---|
| 取消成功 | `已取消 #37 的被取代标记：#38 不再取代它，两条记忆都还在；再用原文召回，它会重新出现。` |
| 本来就没有被取代 | `记忆 #37 本来就没有被取代，未改动。` |
| 目标不在库里 | `注意：记忆 #37 不在库里，未改动任何东西。` |

`supersedes` 与 `unsupersede` **不能同时给**：同时给时整次写入被拒，一条都不落库，回执是
「写入失败：supersedes 与 unsupersede 不能同时给 —— 一个建立取代关系、一个取消它。要改口就只传 supersedes
（并写新的那条）；要撤销改口就只传 unsupersede。这次没有写库。」

### 2.5 edges：两条记忆是什么关系

`edges` 是一个写入参数，形状 `[{type, target}]`：`target` 是已有记忆的 id，`type` 是关系类型。

- **推荐值**：`related`（相关）、`refines`（细化）、`requires`（前提）、`duplicate`（重复）。**取代不在这张表里**：
  它走顶层参数 `supersedes`，写进 edges 的 `supersedes` 会被拒（见本节末的对照表）。
- **自取值**：**以小写字母开头**，其后是小写字母、数字、下划线，≤ 32 字符（写成别的字符集或超长会被跳过）。
- **条数**：一条记忆最多 16 条（固定值，不可配）。
- **不合法只跳过、不拒记忆**：指向自己、目标不存在、这条关系已经存在，都会在回执里逐条写「关系未建立：…，原因」，记忆本身照写。
- **什么时候用**：你知道两条记忆有关系，而且这个关系**不该在重建后消失**。声明的关系是真相源，重建库时保留；推断出来的关系是派生物，重建会整批换掉。

```
lattice_write
  text: "先用备份覆盖目标库，再重新迁；这条做法要求迁移前一定备份。"
  kind: "步骤"
  edges: [{type: "requires", target: 12}]
```

**与 `supersedes` 的区别（最容易混的一条）**：

| 写法 | 改变状态吗 | 回执说什么 | 什么时候用 |
|---|---|---|---|
| 参数 `supersedes: 37` | **会**：旧条被标记「已被 #37 取代」，之后的去重判定认这个标记；召回里旧条被压掉 | 「已把 #37 标记为被 #N（本条）取代（旧条不会删除）。」 | 旧结论作废，换成新条 |
| `edges: [{type: "duplicate", target: 37}]` | **不会**：只记一行关系，不改去重状态 | 「关系 1 条（声明）」＋「（只记录关系，不改变去重状态）」 | 两条讲同一件事，但要留下互指的线索，旧条仍然有效 |
| `edges: [{type: "supersedes", target: 37}]` | **不落**：这条边被拒，记忆照写 | 「关系未建立：supersedes → #37，取代请用写入参数 supersedes；edges 里的 supersedes 不生效」 | 改用顶层参数 `supersedes` |

声明的关系可以用 `lattice_expand` 的 `full` 模式核出来：返回末尾会列「关系（声明）N 条」。

### 2.6 source：同一篇材料切出来的几条

一节材料（一篇文档、一次导出）可能被切成好几条记忆。它们来源相同，正文却常常各讲一件事；
偶尔会有两条几乎逐字相同 —— 那是切分点在重复的段落上。`source` 就是为这种情况给的：**同一次
写入或同一个文件里的几条，传同一个 `source`**。

```json
{ "text": "系统代理必须走本地端口，否则访问境外源会超时。", "source": "网络约定.md" }
```

它只影响一件事：**召回时注入段里的重复压制**。来源相同、正文的 3-gram 覆盖度达到 0.7 的两条，
只留一条（留余弦高的那条），并在段末写 `[另有 N 条与同源内容重复，未列出]`。不同来源的逐字重复
**不压** —— 两篇独立材料里出现同一句话，多半是各自的正当引用。

三条边界：

- **不传就不压。** 没有来源证明不了同源。空来源的条目不参与比较，不会因为「整库都算一个来源」
  而互相压掉。
- **来源不参与检索、不参与判定，也不是权限。** 它不改命中率，不决定一条记忆能不能被另一个项目
  看到（那是 `scope`）。
- **只在写入时给得上。** 已经写进来的条目要补来源，目前没有工具参数可改（改正文请写新条并 `supersedes`）。

### 2.7 回执怎么读

写入的回执是纯文本，几类行分别表示：

| 回执行 | 含义 |
|---|---|
| `已写入记忆 #37：并入已有主题 #12` | 落了库，并入了主题 #12；`新建主题` 表示这是新主题的第一条 |
| `（尚未确认归属，次近主题 #9）` | 落位没把握，两个主题都像。不影响使用，但这类条目值得复查 |
| `入口 5 条（其中显式声明 4 条）` | 这条记忆有几条检索说法，其中几条来自你给的 `refs` |
| `类型「参数」认不出，已按「命令与参数」记。` | kind 被归一，回执明说 |
| `标记：歧义（两个候选接近）（flags=2）` / `标记：未归类；待拆分（按长度切出）（flags=5）` | 落位标记；多个标记用「；」连接，末尾 `flags=N` 是它们的位和（1 待拆分、2 歧义、4 未归类、16 归档）；不改变召回结果，只影响浏览与筛选 |
| `关系 2 条（声明）` / `关系未建立：related → #4，目标记忆 #4 不存在` | 声明的关系落了几条、哪条没落、为什么 |
| `这条 640 个字超过单条上限，已**按长度切成 2 条**分别写入（切点按句边界定，没有按内容判断；过短的段已并回相邻段）。` | 长文本被切。切分时 `topic_hint` **不沿用**：各段各自落位、各自判断主题归属；各段都带「待拆分」标记；每段各起一块，块首多一行 `第 1/2 条：`、`第 2/2 条：`（段数写在句子里） |
| `这条 6000 个字会被切成 10 条，超过一次写入的上限 8 条 —— 这个量已经不是一条记忆而是一篇文档了，**未写入**。请自己按主题拆成多次写入。` | 太长，一条都没写；自己按主题拆成几次写入 |
| `这条只有 9 个字（下限 12），没有独立检索价值，**未写入**。它应当**合并**进它所解释的那条记忆：…` | 碎片被拒收；它该并进它所解释的那条记忆 |
| `已把 #37 标记为被 #N（本条）取代（旧条不会删除）。` | 改口生效；id 不存在时是 `注意：要取代的记忆 #37 不存在，未建立取代关系。`（§2.4） |
| `已取消 #37 的被取代标记：#N 不再取代它，两条记忆都还在；再用原文召回，它会重新出现。` | 撤销改口成功；另两种回执见 §2.4 |

表里的回执照抄原文，`**` 是插件自带的强调标记，不是本文的排版；字数、id、条数随内容与库而变。

## 3. 工具语义边界

### 3.1 五个工具各一句

| 工具 | 做什么 | 不做什么 | 看什么信号 |
|---|---|---|---|
| `lattice_ping` | 健康检查：插件版本、数据目录、编码器状态、配置里显式给过的阈值（未配置时 `thresholds` 是 `{}`）、资源参数、五处缓存的占用（`caches`） | 不写记忆、不改配置、不报告库的结构比例（那是体检，见 §3.2） | `version` 对不对；`encoder` 是 `off` 还是模型名 |
| `lattice_write` | 写一条记忆；过长则按句切分成多条；回执给出落位、入口条数、标记、重复提示与关系结果 | 不删除、不改已有记忆的正文（要改就写新条 + `supersedes`，撤销这次改口用 `unsupersede`）、不自动沉淀、不替你判断「什么值得记」 | 回执里的「已写入 / 未写入」与各类提示；`（尚未确认归属）` |
| `lattice_recall` | 按查询取回记忆，返回装配好的注入段 | 不是搜索界面：不返回结构化命中原样、不分页；除判空与候选上限之外不再按相似度额外过滤（判空时一条都不给，§4.3），候选最多取 topN 条，默认 24，可配 5–50；不保证每条都相关 | 首行库规模、六句固定说法里出现了哪一句、注入段的实际内容 |
| `lattice_expand` | 展开某条记忆全文；`mode` 取 `related` 时看同主题下的其它记忆；顺带列出这条的声明关系 | 不能跨主题检索（那是召回）、不改任何内容 | 正文、状态标记（`已被 #N 取代`、`已归档`）、「关系（声明）」 |
| `lattice_list` | 目录视图：按写入时间倒序列出条目，可过滤、可分页 | 不是搜索：不按相关性排、只给摘要不给正文 | 首行库规模与「共 N 条」；每行的 id / kind / 所有权 / 主题 / 摘要 |

`lattice_list` 的过滤条件与分页：`kind` / `origin`（`user` / `model` / `import`）/ `scope` / `topic` / `flags`；
本页条数默认 20、上限 50（固定上限）；翻页用 `offset`。

`lattice_recall` 可传 `scope`：只召回该域与 `global` 的记忆，不传则不限域。
写入缺省 `global`、召回缺省「不限」，两个默认值不同是有意的 —— 写不知道自己在哪个项目域里，读不该替它选一个。

`lattice_list` 的 `scope` 是同一条语义：给定时**连同 `global` 一起列**（实测传入项目域后，全局条目仍然在列表里）。
`lattice_recall` 另有 `budget`（本次字符预算，覆盖 `viewBudget`，不夹取）。

### 3.2 模型侧没有的三件事

**① 没有删除工具。** 模型侧没有 forget / delete。删除是**界面上由用户执行**的管理动作，归用户。
`src/tools/index.ts` 里有一个删除动作的工具定义，但它**不注册**：模型即使从别处读到这个名字也调不动。
界面调的是插件自己的写路由 `POST /api/lattice-forget`：body 是 `{"atom_id": N}`，要求回环地址与
`content-type: application/json`；200 返回 `{ok, atomId, tombstoneId, deletedAt, kind, scope, summary, alreadyForgotten}`，
404 表示这条不在库里。

- 模型能做的与删除有关的事只有三件：写新条并用 `supersedes` 指向旧条（旧条标「已被取代」）、
  把重复识别出来写进 `refs` 与正文、向用户**提议**删除。
- 用户删过的内容会留下墓碑；模型再写回同一件事时**会被拦下**并说明原因（§4.5）。

**② 没有体检工具。** 结构体检（各表规模、主题与条目比、孤立条目、从未被取回的条目等）是**内部模块 + 只读路由**，
供状态面板显示；`lattice_audit` 这个名字不进模型侧工具表。理由：那些比例只作参考，工具化会把参考值直接递到模型手里，
容易被读成结论。

**③ 没有反馈工具。** `lattice_feedback` 的定义还在代码里（`FEEDBACK_TOOL_SPEC`），但**不进工具表**：
它写的是标签，而 0.5.0 起判定线只吃分布（与本库无关的问句能拿到多高的分数），标签不再是输入。
模型看不到它，也就不会拿它当可用能力去试。将来要重启，先得说清「哪条阈值会被它改写、改写依据怎么复算」。

所以模型侧固定是五个工具：`lattice_ping` / `lattice_write` / `lattice_recall` / `lattice_expand` / `lattice_list`。

### 3.3 调用与副作用的三条纪律

这三条与具体工具无关，是从「插件曾经有一个反馈工具」这段经历里留下的判断。

**① 判断类工具只收语义位置，不收结构 id。** 「第几条」是模型看得见的序号，`atom_id` 是库里的句柄。
一个只记录判断的工具不该携带能解释成「对某条记忆动手」的句柄 —— 收 id 会让「记下第 3 条有用」
与「改第 3 条」在入参上无法区分。反例：删除动作的工具定义现在收 `atom_id`；若将来允许模型
「提议删除」，模型侧该传位置，由插件解析成 id。

**② 跨会话没有意义的数据不落库。** 「最近一次召回是哪几条」只在同一次会话里成立：写进库，
重启后第一次按位置指认就会指到上一次会话的结果。反例：把「上次召回」写进主库，第二天模型说
「第 2 条有用」，命中的是昨天那次召回的条目。

**③ 写是调用目的就明说成败；写是副作用可以静默，但必须写明失败方向。** 写入工具的回执必须回答
「写进去了没有」；召回顺带做的旁路写入（命中计数等）失败时不必打断召回，但要在代码里写明
「宁可少记，不可少给」这类失败方向，免得后来的人把它当缺陷修成阻塞。反例：给召回加一条
「旁路写失败就报错」的分支 —— 一次写盘失败会让整次召回不可用。

## 4. 失败与降级时看到什么

总纪律先写在前面：**降级必须留痕，拦下必须说明。** 任何「悄悄少给了点什么」都是缺陷，不是设计。

### 4.1 编码器不可用

- **召回照常返回**，首行下多一句 `（编码器不可用，本次为纯词面召回）`。
- **判定停用**：参考分布要靠编码 48 条内置问句算出来，编码器不可用时算不了，于是**不判**
  「库里有没有内容」—— 宁可照常给前几条，也不按一条不存在的线判成「没有」。所以这种情况下
  不会出现 §0.5 第一行的判空句。
- **排序退回词面**：没有向量就没有余弦，候选按词面通道的名次排。
- **写入仍然成功**，但那一条没有向量，以后只能靠词面命中。
- **不报相似度**：分数是本插件内部的刻度，跨库不可比，所以任何情况下都不显示数字。
- **看什么信号**：`lattice_ping` 的 `encoder` 是 `off` 还是模型名。

### 4.2 词面路失效与短查询落空

| 召回文本里的句子 | 含义 | 该做什么 |
|---|---|---|
| `（词面两路均未命中，仅向量路有结果）` | 这次只有向量路给出结果 | 结果仍可用；反复出现要查索引 |
| `（查询含两字词但入口层零命中）` | 两字词在入口层一条都没命中，通常意味着切词或索引有问题 | 换一个词再查一次；反复出现要查索引 |
| `没有找到相关记忆。` | 一条都没命中 | 换用户的原话、俗称或报错原文再查 |

### 4.3 判空：库里没有针对这个问题的内容

`库里没有针对这个问题的内容。`（此时一条记忆行都不给）

判据是相对量：这条查询的最高余弦，与本库里 48 条内置问句各自的最高余弦比。低于它们的
90 分位就判「没有内容」。所以它**不保证**库里真的没有 —— 边界上的真内容会被判成没有
（用同一批问句在两个语料上交叉验证，越线率 10.4%，这批问句本身就在这个水平上）。

- 处理：换问法再查一次，或用 `lattice_list` 确认库里到底有没有这件事。
- 不要因为这一句就答「没聊过」：它说的是「按我的尺子没量到」，不是「库里没有」。

### 4.4 库还小：判定不可靠

`库里只有 N 条，判定还不可靠；以下是按相关度列出的前几条。`

参考分布由 48 条内置问句在本库实算得出。库里的条目比这 48 条还少时，参考线本身就不稳，
这时**不判**「有没有内容」，只按相关度列前几条，并明说判定不可靠。

- 该做什么：正常用。库长到几十条以后这句话自己就消失了。
- 这句话不会与 §4.3 同时出现：判定不可用时谈不上判空。

### 4.5 写回被墓碑拦下

用户删过某条记忆，你写同一件事（词面或语义高度重合）时会**被拒**，回执给出墓碑与相似度：

```
写入被拒：这条内容与用户删过的一条记忆重合（词面与语义都重合）。
  原记忆 #42（结论，global）：……
  删除于 2026-05-04，墓碑 #7。
  相似度：词面 0.812，余弦 0.904。
用户删除过的内容不会被重新写入。若这确实是一件新的事，请换一个角度写清楚它与原记忆的区别；不要重复提交同一句话。
```

- 「重合」有第二种说法：只靠语义命中时写「语义高度接近（词面改写较大）」；没有向量可比时相似度行写
  「余弦 未算（无向量）」。
- **不要重试同一句话**，也不要换一种说法表达同一个意思。
- 确实是新事 → 写清它与原记忆的区别（前提变了、结论不同、适用范围不同）。
- 墓碑比对有上限：回执末行提示「只比对了最近 N 条」时，说明库里的墓碑较多。

### 4.6 归档条目

归档是**可见性**动作，不是删除：内容、入口词、关系都还在库里。

| 场景 | 会看到什么 |
|---|---|
| 默认召回 | 不会出现：归档条目不进注入段，也不作为图路的邻居进入候选 |
| `lattice_list` 默认 | 不列出 |
| `lattice_list` 给 `flags` 为 16 | 只列归档条目，每行带「已归档」 |
| `lattice_expand` 按 id 展开 | **仍能展开**，首行会带「已归档」 |

模型侧没有归档 / 取消归档的工具：这是用户界面上的动作。

### 4.7 「你以为会这样」与「实际会看到」的对照

| 你以为会这样 | 实际会看到 |
|---|---|
| 库里没有这件事 → 召回说没有 | 召回说「库里没有针对这个问题的内容」时，它说的是「按本库的尺子没量到」，量不到也可能是问法不对：换说法再查 |
| 写入成功 = 写对了 | 成功只说明落了库；写得准不准，要看抽样召回（§1.3） |
| 检索不到 = 那条被删了 | 可能只是归档（§4.6）或被取代（§2.4）：归档默认不列出，被取代的旧条在召回里被压掉；用 `lattice_list` 或 `lattice_expand` 能看到它们 |

## 5. 术语（第一次出现的地方）

| 词 | 一句话解释 |
|---|---|
| **一条记忆**（atom） | 库里最小的语义单位，一条讲一件事；工具返回的 `#37` 就是它的 id |
| **主题**（topic） | 若干条记忆的归组，由写入时的几何计算决定归属；不是人工目录 |
| **入口**（entry） | 一条记忆的检索说法（别名、关键词、从使用中学到的词）；只参与检索，不影响正文 |
| **图路** | 候选的一路：从命中的记忆出发、沿一跳边扩展。它只影响「谁进候选」，不在注入段里单独成段 |
| **预算** | 一次注入最多给多少字符（默认 5000）。装填按相关度逐条进行，装不下就停，剩余条数说在段末 |
| **参考分布** | 48 条与库无关的内置问句在本库各查一次，取各自最高余弦的 90 分位。判定「有没有内容」拿这条线的位置比，所以它是相对量、随库现算（§0.5） |
| **墓碑** | 用户删除后留下的记录（不含正文），用于阻止同一内容被重新写入（§4.5） |
| **归档** | 让一条记忆默认不被检索到，但内容与关系都保留（§4.6） |
| **声明边 / 推断边** | 声明边是模型用 `edges` 写下的关系（重建后仍在）；推断边是插件按几何算出来的关系（重建会整批换掉） |
| **取代 / 取消取代** | 新条用 `supersedes` 把旧条标成「已被 #N 取代」：旧条不删，但默认不列进召回；`unsupersede` 只清掉这个标记（§2.4） |
